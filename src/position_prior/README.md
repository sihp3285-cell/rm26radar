# position_prior

逐兵种条件位置先验的 ROS 2 shadow-mode 包。它订阅 `/world_targets`，只在目标真实观测丢失后发布独立的 `/prior_predictions`，不会覆盖 `WorldTarget`，也不会把猜点回灌 tracker。

## 在线约定

- 输入角色：英雄、工程、步兵 3、步兵 4、哨兵（模型名分别为 `hero`、`engineer`、`infantry3`、`infantry4`、`sentry`）。
- canonical 坐标固定为红方视角；蓝方使用 `(28-x, 15-y)` 中心对称。
- `2/5/10 s` 使用最邻近 horizon；物理可达距离使用真实 `lost_duration_s`，不使用离散 horizon 代替。
- `generated/RB2026_navgrid_v1.json` 为五个兵种分别提供 0.2 m 可通行网格。在线按最大台阶高度、禁止对角穿角的八邻域 Dijkstra 最短路径判断可达性，不再用隔墙直线距离代替实际路程。
- 每次最后可靠观测只计算一次最短路径距离场，整个丢失周期复用，避免逐帧重复搜索；模型候选和最终融合点都会吸附到相同兵种、相同连通分量的可通行网格。
- 候选还必须位于最后可靠观测点的 `max_guess_distance_m` mesh 路径硬阈值内；阈值内使用高斯路径距离权重温和偏向近点。未加载 navgrid 时保留欧氏距离回退。
- `home.yaml` 和 `gully.yaml` 是全兵种盲区，`engineer.yaml` 只对工程兵生效。最后可靠点位于或靠近盲区时，系统会从盲区内的兵种可通行网格注入候选并分配可配置概率质量；不可达或超过真实丢失时长路程上限的盲区格不会参与猜点。
- `gully.yaml` 会中心对称补全场地另一侧沟区，并把候选限制在最后观测点所在的 mesh 高度层（默认 ±8 cm），避免跨层跳到浅色中心岛。不能简单选择 PLY 的全局最低表面：同一平面坐标可能同时包含地面、结构底面和可行驶面。
- 离线模型的 `stay_probability` 会在最后可靠位置注入驻留锚点。盲区内默认至少分配 70% 先验质量；运动似然仍可在速度足够可靠时把主猜点沿 mesh 通道向前推进。这样车辆因高低差遮挡且实际低速驻留时，不会被远端统计热区拉偏约一米。
- 最后一帧速度只作为短期方向证据，默认按 3 s 时间常数衰减并使用衰减速度的积分位置；不会再把很小的速度噪声按几十秒匀速外推到场地边界。mesh 物理可达距离仍按真实失联时长计算。
- 运动门控还会读取 tracker 的速度协方差。相机视线方向或 PLY 高度边界导致速度不确定时，该方向速度会被降权，不能单独把猜点拉离驻留锚点。
- `enabled_roles` 控制当前允许输出的兵种；当前配置开启全部五个兵种以继续收集 shadow 数据，并应按兵种分别比较重识别误差。
- 最后可靠位置必须通过连续观测确认：默认连续 3 次检测位于 0.8 m 聚类半径内，单帧跳变不会刷新先验锚点，也不会结束正在进行的猜点。
- 猜点按“阵营 + 兵种”唯一化，同一方同一兵种最多输出和显示一个；实战运行时再由敌我门控只保留敌方结果。
- 猜点只服务敌方：蓝方视角只接受红方目标，红方视角只接受蓝方目标；己方和未知阵营不会建立或保留先验缓存。
- 达到 `guess_after_s` 后持续猜点；超过模型最大 horizon 时继续使用最邻近的 10 秒档，直到该车辆被真实重新观测。
- 真实观测会立即退出本轮猜点并刷新缓存；机器人被明确判死、输入时间非法、时间倒退或阵营翻转会清除缓存。
- tracker 的 `DEAD/INVALID` 仅表示短期跟踪生命周期结束，不清除最后一次可靠观测。
- 模型缺失、版本不符、geometry 不符或 SHA-256 不符时，节点保持运行但安全禁用输出。

## 输出

`PriorPredictionArray` 中每个结果包含主猜点、Top-K 候选、置信度、样本量、熵、fallback 层级、运动门控状态、mesh/盲区状态、驻留锚点质量和拒绝原因。候选同时输出 mesh 最短路径距离、直线距离、是否来自盲区以及是否为驻留锚点。地图只以洋红菱形和空心候选圆显示这些结果；`RadarMap` 与 `MapAnalyzer` 仍只使用 tracker 数据。

地图叠加会与 `flip_team` 的最终显示视角同步：红方视角下底图旋转 180° 后，主猜点和候选点也使用相同的显示坐标变换，避免正确的沟底 world/canonical 点被画到中心对称位置。

shadow CSV 记录 `PREDICTION` 和 `REACQUIRED` 两类事件。后者包含重识别位置与最终误差，可用于后续实战评估。

## 模型与测试

模型目录 `position_prior_toolkit/` 在仓库根目录的 `.gitignore` 中。默认模型：

```text
position_prior_toolkit/run_v1/04_rmuc2026_position_prior_v1.yaml
SHA-256: b1a7384042939aca3fcfa3d45a5bbd3cd8b7e3bdeaa658aac24d17f36e2df53e
```

`test_model_golden` 会加载真实模型，并逐项核对 `06_golden_cases.json` 中全部 15 个 Python golden cases。

`test_navigation_mesh` 会逐项核对 `RB2026_navgrid_golden_v1.json`，并覆盖全兵种/工程专用盲区隔离、盲区候选注入和最终 mesh 落点。

首次构建 ROS 接口前应退出与系统 ROS 版本不一致的 Conda 环境。Jazzy 的 `ros2` CLI 使用系统 Python 3.12；若误用其他 Python 生成 `rosidl` 绑定，C++ 节点仍可运行，但 `ros2 topic` 无法加载自定义消息。
